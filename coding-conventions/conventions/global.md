Write clear, self-documenting code. Prefer readability over cleverness.

Keep functions small and focused on a single responsibility.

Handle errors explicitly — don't silently swallow failures or return values.

Write tests for new logic. No commented-out dead code; use git history instead.

When a project has established conventions (linter configs, style guides, project AGENTS.md), follow them — project-specific rules take precedence over these guidelines.

Be consistent with existing code in the file or subsystem being modified.
